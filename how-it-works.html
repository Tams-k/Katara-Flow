From report to resolution

  1. A resident reports. They choose what is wrong, say where the drain is and add a short description.
  2. NCWSC reviews. The report appears in a list for NCWSC staff, who move it to In progress when work starts.
  3. NCWSC resolves. When the problem is dealt with, staff mark it Resolved in the system.
  4. The resident is told. Every change of status sends a notification back to the person who made the report.

The path is deliberately simple: Reported, then In progress, then Resolved. The only thing that loops back is the notification to the resident.

The three modules

  • Dashboard

    Where residents submit reports and see the status of their own reports.

  • Status review

    Where NCWSC staff view reports and move them from Reported to In progress to Resolved.

  • Notification engine

    Picks up each status change and alerts the resident automatically.

Each module can be built, tested and shown on its own, which keeps the system easy to maintain and to grow.

Two roles, two sets of permissions

  • Resident

    Can create reports, see the status of their own reports and receive notifications. Cannot change a status.

  • NCWSC staff

    Can review reports and update their status. Confirmation that a problem is resolved is made inside the system.

Built to be light

Katara Flow runs in an ordinary web browser, so nobody has to install anything. It is built with HTML, CSS and JavaScript on the front end and a relational database behind it. The pages are kept small, because many of the people who need the system have slow or unreliable connections.

At a glance

  • Every report moves through three stages: Reported, In progress and Resolved.
  • Katara Flow covers drainage problems in Nairobi only. It does not cover roads, waste collection or electricity.
  • Built to be light, so it works on a slow connection. Report a drain.
